# Workshop ideas
Last edited: 2026-05-27
Status: Active
Scope: Canonical home for durable parked ideas and pre-approval concept packets
Related files: `../product/README.md`, `../standards/doc-routing.md`, `../standards/documentation-model.md`, `../templates/workshop-idea.md`

Use this folder for ideas that are worth preserving, discussing, and revisiting later even though they are not yet approved product behavior or active implementation work.

## When to use this folder

Store things like:

- tabled ideas after a useful discussion
- pre-planning concept packets you want humans to browse later
- proposal-stage notes that are durable enough to deserve a canonical home
- parked problem statements with constraints, open questions, and resume triggers

## Do not use this folder for

- approved product behavior that should live in `../product/`
- architecture or implementation-shaping reference that should live in `../system/`
- active execution notes, plans, or task packets that belong in `../../work/`
- sparse rationale-only tradeoff records that belong in `../decisions/`

## Naming

Use hyphenated lowercase filenames with no spaces, for example:

- `auth-redirect-cleanup.md`
- `bulk-invoice-editor.md`
- `smarter-sync-conflict-flow.md`

Inside the file, keep a human-readable `# Title`.

## Suggested doc shape

A workshop-idea doc should usually include:

- `Status`
- `Decision owner`
- `Drafted by`
- `Approved by` when applicable, or `n/a`
- `Resume trigger`
- idea summary or problem statement
- current understanding
- constraints
- open questions
- why it is parked or proposed
- what would make it ready to resume or promote
- related docs
- changelog

Use `../templates/workshop-idea.md` as the starter.
